 Plan de Implementación: Sistema de Pagos con  
 Mercado Pago

 Resumen Ejecutivo

 Implementar un sistema de pagos completo para 
  la plataforma de carpooling, integrado con   
 Mercado Pago, que permita:
 - Cobrar a pasajeros al reservar
 - Dividir pagos automáticamente (85%
 conductor, 15% plataforma)
 - Wallet para conductores con historial y     
 retiros
 - Liberación de fondos post-viaje

                           |

 1.2 Base de Datos (MySQL - Puerto 3309)       

 Tablas a crear:

 1. seller_accounts - Conductores vinculados a 
  MP
   - user_id, mp_access_token (encriptado),    
 mp_refresh_token, status
 2. payments - Pagos de reservas
   - booking_id, passenger_id, driver_id       
   - amount, platform_fee (15%), driver_amount 
  (85%)
   - mp_preference_id, mp_payment_id
   - status (pending/approved/refunded)        
   - fund_status (held/released/refunded)      
 3. wallets - Balance de conductores
   - available_balance, pending_balance,       
 held_balance
   - total_earned, total_withdrawn
   - auto_withdraw_enabled,
 auto_withdraw_threshold
 4. wallet_transactions - Historial de
 movimientos
   - type (credit/debit/hold/release)
   - amount, balance_before, balance_after     
   - payment_id, withdrawal_id
 5. withdrawals - Retiros solicitados
   - amount, fee, net_amount
   - status
 (pending/processing/completed/failed)
   - mp_transfer_id
 6. processed_events - Idempotencia

 Flujo de Pago Completo

 1. Pasajero selecciona viaje y asientos       
    ↓
 2. Crea booking (status: pending_payment)     
    ↓
 3. Crea preferencia MP con split:
    - 85% → conductor
    - 15% → plataforma
    ↓
 4. Redirige a checkout MP
    ↓
 5. Pasajero paga
    ↓
 6. Webhook: payment.approved
    ↓
 7. Booking confirmado, asientos reservados    
    ↓
 8. Viaje se completa
    ↓
 9. Timer 2h o pasajero confirma
    ↓
 10. Fondos liberados al wallet del conductor  
    ↓
 11. Conductor puede retirar a su cuenta MP

 Consideraciones de Seguridad

 1. Tokens OAuth encriptados con AES-256       
 2. Validar firma de webhooks de Mercado Pago  
 3. Rate limiting en endpoints de retiro       
 4. Idempotencia con event_id en todos los     
 eventos
 5. Auditoría de transacciones financieras     
 6. No almacenar datos de tarjetas (solo       
 tokens MP)

 Paso 1: Crear cuenta de desarrollador

 1. Ir a
 https://www.mercadopago.com.ar/developers     
 2. Click en "Crear cuenta" o iniciar sesión   
 3. Completar verificación de identidad        

 Paso 2: Crear aplicación

 1. Ir a https://www.mercadopago.com.ar/develo 
 pers/panel/app
 2. Click en "Crear aplicación"
 3. Nombre: "CarPooling App"
 4. Modelo de negocio: Marketplace
 5. Tipo: Pagos online

 Paso 3: Obtener credenciales de prueba        

 En el panel de la aplicación:
 - Public Key: Para frontend (checkout)        
 - Access Token: Para backend (API calls)      
 - Client ID: Para OAuth
 - Client Secret: Para OAuth

 Paso 4: Configurar URLs de OAuth

 En la configuración de la aplicación:
 - Redirect URI: https://tu-dominio.com/api/v1 
 /seller/oauth/callback
 - Para desarrollo:
 http://localhost:3000/seller/callback

 Paso 5: Configurar Webhooks

 1. Ir a "Webhooks" en el panel
 2. Agregar URL: https://tu-dominio.com/api/v1 
 /webhooks/mercadopago
 3. Eventos a escuchar:
   - payment (pagos)
   - merchant_order (órdenes)

 Paso 6: Usuarios de prueba

 1. Ir a "Cuentas de prueba"
 2. Crear 2 usuarios:
   - Comprador: Para simular pasajeros

 ANEXO B: Checkout con Deep Link (Mobile)      

 Flujo de Pago

 1. Usuario confirma reserva
    ↓
 2. App llama: POST /payments/preference       
    ↓
 3. Backend crea preferencia en MP
    ↓
 4. Backend retorna: { init_point, 
 sandbox_init_point }
    ↓
 5. App abre URL con 
 Linking.openURL(init_point)
    ↓
 6. Usuario paga en MP (app o navegador)       
    ↓
 7. MP redirige a:
 carpooling://payment/success?payment_id=xxx   
    ↓
 8. App captura deep link y muestra 
 confirmación

 Configuración Deep Links

 app.json (Expo):
 {
   "expo": {
     "scheme": "carpooling",
     "android": {
       "intentFilters": [{
         "action": "VIEW",
         "data": [{ "scheme": "carpooling" }]  
       }]
     },
     "ios": {
       "bundleIdentifier":
 "com.tuapp.carpooling"
     }
   }
 }

 URLs de retorno (enviar a MP):
 success: carpooling://payment/success
 failure: carpooling://payment/failure
 pending: carpooling://payment/pending

 Código de Ejemplo (React Native)

 import * as Linking from 'expo-linking';      

 // Crear preferencia y abrir checkout
 const handlePayment = async () => {
   const { init_point } = await
 paymentsService.createPreference({
     booking_id: bookingId,
     return_url: 'carpooling://payment'        
   });

   await Linking.openURL(init_point);
 };

 // Escuchar retorno (en App.tsx o screen)     
 useEffect(() => {
   const subscription =
 Linking.addEventListener('url', ({ url }) =>  
 {
     if (url.includes('payment/success')) {    
       // Mostrar confirmación
     } else if
 (url.includes('payment/failure')) {
       // Mostrar error
     }
   });

   return () => subscription.remove();
 }, []);
